Primero, un laboratorio.

La web y la consola vienen dentro del binario Go. El laboratorio usa un destino simulado persistente: sus permisos nunca habilitan acceso a bases, servicios o cuentas reales.

Ejecutar

go build -o lease ./cmd/lease
./lease demo --dir ./lease-lab \
  --listen 127.0.0.1:8789 --seed

Abrí la dirección que imprime el comando. --seed crea ejemplos sólo si el libro está vacío. Al reiniciar conserva las solicitudes y reconcilia los permisos pendientes. Ctrl+C detiene el proceso.

Probar el recorrido

  1. En la consola, elegí a Inés y solicitá acceso con una justificación.
  2. Cambiá al rol simulado de Mateo. Aprobá o denegá la solicitud.
  3. Revisá el estado activo, su ventana de tiempo y la evidencia.
  4. Revocá el acceso o usá una duración de 10 segundos para observar el vencimiento.

El selector de personas es una simulación de roles. No autentica usuarios y la consola sólo admite el proveedor de laboratorio y conexiones loopback.

Operar desde la terminal

./lease init --db ./broker.sqlite --config examples/lab.json
./lease request --db ./broker.sqlite --config examples/lab.json \
  --as user:ines --entitlement analytics-read \
  --ttl 5m --reason INC-284
./lease list --db ./broker.sqlite --config examples/lab.json

Usá el ID devuelto con approve --id ID --as user:mateo o revoke --id ID --as user:ines, pasando el mismo --db y --config. run ejecuta el worker continuo; reconcile ejecuta una pasada. El worker libera el lock entre pasadas para que los comandos locales puedan operar. Sólo una operación actúa sobre el destino a la vez.

PostgreSQL

El adaptador crea un rol temporal NOLOGIN y lo asigna a un login existente mediante un mapeo explícito. Sólo observa los objetos de su namespace. Al revocar, retira las membresías y termina las sesiones de ese login en el clúster, incluidas las que no usaron Lease.

Usá primero scripts/test-postgres.sh: crea y destruye un clúster propio sin tocar las bases del host. El contrato, la configuración y sus límites están en docs/postgres.md dentro del repositorio.

Qué protege cada límite

  • La CLI confía en el usuario del sistema operativo. --as atribuye decisiones; no demuestra identidad.
  • La política limita solicitantes, aprobadores y duración. No hay autoaprobación en este corte.
  • El worker debe permanecer disponible para revocar en plazo. La caída del broker puede extender un permiso.
  • Los hashes detectan inconsistencias locales. No son una firma ni un anclaje externo.
  • OIDC, otros proveedores y una consola para destinos reales siguen pendientes.

Servir sólo la web

./lease site export --out ./lease-site

Exporta HTML, CSS, JavaScript e imágenes para hosting estático. La consola necesita el comando demo para operar; al abrirla sin backend muestra instrucciones. Este comando prepara archivos y no publica el sitio.
